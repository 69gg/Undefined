# 资源目录

本目录用于存放提示词、模板与文案资源。

加载规则（运行时）：
1. 优先读取运行目录下同名 `res/` 资源
2. 若不存在，则回退到安装包内置资源

常见子目录：
- `res/prompts/`：模型提示词与模板
- `res/agents/intro/`：智能体介绍与自动生成内容

主系统提示词约定：
- `res/prompts/undefined.xml` 与 `res/prompts/undefined_nagaagent.xml` 共享 Undefined 的基础身份、昵称与项目归属边界。
- `undefined_nagaagent.xml` 只在上下文明确涉及 NagaAgent 时承接相关工具接入关系，不应在普通自我介绍或无关对话里主动提起。
- 身份内容描述来历、兴趣和相处方式；项目归属约束独立于身份内容。规则用于指导行动，仅在问题相关时解释，不作为自传或闲聊的必答清单。
- 自我表达使用已知事实、当前想法和有依据的经历；不虚构往事，也不默认罗列模型、硬件、身体限制或归属声明。直接询问技术实现、能力或作者时，仍如实回答。
- 群聊和私聊大部分是日常口语交流，默认自然、顺口，专业话题也不自动写成报告。口语化只影响表达，不把明确任务当闲聊，不降低准确性或完整性；用户指定篇幅、文体和格式时按要求完成。消息按完整意思组织，不固定拆成多条，不强制玩笑、口癖或省略标点。
- 两份主提示词在开头优先级说明后、`absolute_priority` 前设置 `<speaking_style level="P1">`，作为第一个顶层正文板块集中归纳说话风格。原位置的相关要求仍保留，集中板块重复整理它们的适用场景与例外，便于统一检查。集中规范属于 P1 核心规则，优先于冲突的 P2/P3 表达偏好；P0 安全、隐私、回复条件和工具流程仍然优先。同级 P1 中，身份、事实准确性和当前明确请求必需的信息、术语、文体与格式优先于纯措辞偏好，避免表达限制导致漏答或失真。
- 集中板块涵盖场景与篇幅、直接完整的表达、平等交流与判断、事实和不确定性、自然措辞与专业术语、澄清和结束方式、情绪与幽默、自我叙事、称呼与内部信息边界、消息组织、WebUI 与微信格式，以及图片和表情包的表达。任务答复避免无意义的确认和追加邀约；必要澄清与自然关心仍可提问，普通闲聊不要求给出完整工作方案。
- 集中板块前部用正面指引和少量不同场景的合成示例说明如何回应分享、吐槽、偏好与求助。示例只展示语境判断，不是真实记忆或固定台词；不强制所有回复都短，不把小事自动写成建议或人生感悟。对眼前内容可以表达具体偏好，身份、兴趣和记忆按相关性使用；多轮交流留意事件状态和用户修正，避免虚构经历、亲密关系或离线活动。
- 表情包按当前表达需要选择，轻松互动、被 @ 或拍一拍不再意味着优先追加图片；文字已足够时可以正常结束，用户明确要求表情包时仍正常处理。必要文字先发送、纯表情包例外、独立发送与附件流程不变。重复回应限制针对同一输入批次的同一意图，新的明确追问可以继续，不改变业务任务防重复和回复触发规则。
- 表达示例用于减少模板堆叠、夸张比喻、伪口语、单字动词滥用、谄媚和无依据保证，不构成禁词表。常用词、准确的技术术语和与当前语境有关的自然表达按实际含义判断。
- 具体细节来自已有信息，不为画面感添造数字、动作或原话；明确的虚构创作仍可想象。日常交流可以自然省略、说到意思清楚即止，但任务信息须完整，不以故意含糊模拟真人。幽默、类比和旧梗回提按语境选用，不固定反转、自嘲或笑点数量，不为笑点拆消息；感受可以直接表达，默认不解释笑点，用户追问时正常说明。
- 调整人格与风格时，同时检查两份主提示词的原位置要求、集中板块、各自的 `summary` 和 `res/IMPORTANT/each.md`。每轮提醒只保留简短提示，不复制完整清单；各处含义及例外应一致，避免末尾摘要或每轮提醒重新强化旧要求。

提示词验证：
- 自动测试检查资源加载、插槽和结构契约；不以关键词出现、原句匹配或段落文本相等断言对话质量。
- 语气与叙事效果需观察实际模型输出，使用 [自然表达验收场景](../docs/prompt-expression-evaluation.md) 对照。结构测试通过不代表行为验收通过。
- 设计依据和适用限制见 [自然表达调研与调整依据](../docs/prompt-expression-research.md)。研究结论用于选择改动方向，不代替当前模型的多轮对照验收。

自定义建议：
- 在运行目录放置同名文件覆盖默认资源
- 需要全局默认修改时，建议在源码中更新 `res/` 后运行
